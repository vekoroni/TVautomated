## 0. Headline finding (see full detail in §4)
The per-ticker detail modal (8 tabs: Overview, Trade Setup, Convexity, Stage Ladder, Morning Val, EIL, Q-OMEGA, and part of Options) and several columns of the main signal table read field names with legacy prefixes (`sb_*`, `mv__*`, `wbs__*`, `doss__*`, `eil__*`, `garch__l3_*`, `qomega_*`, plus unprefixed legacy names such as `contract_strike`, `recommended_contract`, `options_strategy`, `live_vwap`). None of these keys exist in `FINAL_BOOK_FIELDS` (`contracts/lab_control.py:45`), and empirically **none of them are present in a single row of the reference governed run** (`data/output/runs/20260824_220616/intelligence_lab/final_opportunity_book_20260824_220616.json` — verified programmatically, zero matches out of ~55 probed legacy keys). Because `intelligence_lab.py:1880` replaces `result["signals"]` wholesale with governed rows whenever `_governed_lab_book()` succeeds (which it does for this run — confirmed via `contracts/lab_control.py` / `intelligence_lab.py:202-218`), every UI expression built from those legacy keys silently falls back to its `'—'`/`0`/`false` default. This is not a data-missing condition (`NOT_EVALUATED`/`MISSING_DATA_DEFECT`); the governed book usually *does* carry the equivalent field under its contract name (e.g. `wbs_grade`, `morning_execution_permission`, `eil_signal_verdict`, `garch_iv_tailwind_score`, `readiness_stage`, `ts_checkpoint_rule`), but the UI never reads that name. Full field-by-field evidence is in §4.

## 1. Flask routes (`intelligence-lab/intelligence_lab.py`)

Reports `RUNS_DIR` existence, run count, latest run id, server time, hardcoded `"version": "2.1 — governed Lab signal book"` (2337). The version string is a hardcoded literal, not derived from `lab_schema_version` — DISPLAY_ONLY but the label text itself is not verified against the actual governed-book status of the latest run (HARDCODED-label defect candidate, low severity — see gap report).

### `/api/runs` — 2340-2343
Lists run ids via `_list_runs()` (250-263), which reads `RUNS_DIR` subdirectories, excludes the literal `"latest"` folder, sorts descending, then re-orders using `data/output/latest.json`'s `run_id` if present. Run-selection logic is entirely file-system/manifest-derived, not hardcoded.

### `/api/run/<run_id>` — 2345-2347, `/api/run/latest` — 2349-2354
Both call `_load_run(run_id)` (1070-1899+) and `_slim_lab_payload(...)`. `_load_run` first builds a legacy signal frame from `eil_enriched_{run_id}.csv` (1084-1092, comment: "PRIMARY SIGNAL SOURCE... 232 cols" — this is a *different* 232-column file from the governed book and must not be conflated with `FINAL_BOOK_FIELDS`; UNVERIFIED whether the two 232-column sets are identical, not confirmed in this audit), merges SuperBrain/execution/etc, computes `sb_*` derived fields (1800-1841) and `research_priority_score`/`priority_score` (1834-1841), applies `apply_lab_resolution` (1848), then **at 1877-1888 unconditionally overwrites `result["signals"]` with `dict(row) for row in governed_book.get("rows", [])`** when `_governed_lab_book(run_id)` returns truthy. `result["lab_signal_source"]` is set to the literal string `"GOVERNED_FINAL_OPPORTUNITY_BOOK_V2"` (1881) or `"LEGACY_IN_MEMORY_ASSEMBLY"` (1884) — **this assertion is genuinely data-derived, not hardcoded-always-true**: `_governed_lab_book` (202-218) checks `lab_schema_version == "lab_signal_book_v2"`, `rows` is a list, and `candidate_count == len(rows)` before returning the payload; any failure returns `{}` and the Lab falls back to the pre-1877 legacy assembly. DISPLAY_ONLY / CONTROL for `lab_signal_source` itself. However, all the `sb_*`/pre-governed enrichment computed at 1800-1841 is discarded once governed rows replace `result["signals"]` — **except that the UI (§4) still reads those discarded field names**, which is only harmless if the governed row happens to carry a same-named key, which it does not (verified, §4). Caching: `_run_cache` keyed by `run_id`, invalidated via `_lab_cache_signature` (1074-1077).

### `/api/enter_trade` (POST) — 2437-2508+
Loads the signal for `ticker` from `_load_run(run_id)["signals"]` (2470-2474), then **re-resolves `lab_verdict`/`lab_tradeable`/`conflict_state`/etc via `resolve_lab_tradeability(sig, manifest, open_trades)` (2477) and overwrites `sig` in place (2478-2489)** before gating entry on `resolved["lab_tradeable"]` and `resolved["lab_verdict"] in {"GO","GO_LIMIT","PROBE"}` (2500-2502). Not a UI/JS derivation, but flagged as a resolution point worth listing: if `resolve_lab_tradeability`'s logic ever diverges from the book-writer's logic, a trader could see one verdict on screen (from the governed book) and get a different accept/reject decision when clicking Enter Trade. ### `/api/open_contracts` — 2681-2707
Reads `vanguard.trade_contract.list_open_contracts()/load_contract()` — an UNGOVERNED_SOURCE relative to the Lab book (separate trade-contract store). DISPLAY_ONLY, error-tolerant (`except: pass` per contract, 2704 — silently drops unparsable contracts with no user-visible warning, a silent-failure defect).

### `/api/export_csv` — 2709-2760
Filters `_load_run(run_id)["signals"]` by verdict/rr/ev/match-type/catalyst/behaviour-hash, then streams a CSV. **Verdict filter at 2727 falls back through `s.get("lab_verdict","") or s.get("options_verdict","") or s.get("sb_final_verdict","")`** — the second and third fallbacks (`options_verdict`, `sb_final_verdict`) are legacy/ungoverned field names not in `FINAL_BOOK_FIELDS`; harmless only because `lab_verdict` (governed, field 8) is populated on every governed row and short-circuits the `or` chain — but this is a live UNGOVERNED_SOURCE fallback that would silently activate if `lab_verdict` were ever blank. AUTHORITY_RISK / WRONG_SOURCE for the rr_min/ev_min filters specifically — a trader applying an R:R or EV floor via the export filter gets an unfiltered result set with no error.

### `/api/kpi` — 2764-2867
Computes an aggregate scoreboard across the last N runs from `_load_run(rid)["signals"]`, keying on `mv_verdict`, `direction`, `data_quality_state`, `no_match`, `signal_trust_score`, `mv_breakdown` (2794-2817). **None of `mv_verdict`, `data_quality_state`, `no_match`, `signal_trust_score`, `mv_breakdown` are in `FINAL_BOOK_FIELDS`** (confirmed absent from the reference run's row keys). `direction` is governed (field 33) and works. HIGH-severity WRONG_SOURCE defect — see gap report.

### `/api/monitor_positions` — 2879-2979, `/api/log_exit` (POST) — 2982-3094, `/api/capture_outcomes` (POST) — 3097-3151, `/api/outcomes` — 3154-3237, `/api/learning_feedback` — 3241-3249
