1. Context and Problem Statement
1.1 What the Pipeline Interpreter Does Today
The Pipeline Interpreter is a standalone CLI application that sits outside the AVSHUNTER pipeline. It reads pipeline output CSVs as read-only inputs and produces trade-execution narratives through the Dr. Magnus Vale and Soul of the Chart frameworks. It has no shared code, no shared state, and no runtime coupling with intelligent_orchestrator.py or morning_thesis_validator.py.
The interpreter produces expert-level trade narratives. Every verdict, trigger level, kill switch, and execution prescription is written for an experienced trader who can translate "PROBE | ARMED_AWAITING_TRIGGER" directly into action.
1.2 The Gap
Two gaps exist in the current output:
Junior traders cannot consume the output without significant interpretation. The plain-language layer is absent — every verdict requires cross-referencing multiple sections to understand what to do.
The output is a snapshot, not a story. A trade that takes 2-3 sessions to form has no continuity mechanism. Each day's interpreter run is disconnected from the previous day's analysis.
1.3 The Enhancement
This document defines the architecture for adding two capabilities to the existing interpreter:
Story of the Trade — an eight-section junior-readable output layer that explains every section in plain English and shows all interdependencies explicitly
Thesis Lifecycle Management — a cross-session continuity system that tracks thesis state from first formation through execution or closure, including overnight delta detection

5.1 Gamma Section — Mandatory Sub-Elements
Section 2 (Market Makers & Gamma) must explain three specific concepts as a cascade, showing how each connects to the next. These are non-negotiable for the junior trader audience:
Gamma flip zone — the price level where dealer hedging switches from dampening to amplifying. Below this level, moves accelerate. Must state the exact price from the pipeline row.
Gamma island — the sparse OI zone between the gamma flip and the next major support. Must explain that price moves fast through this zone with no natural brake.
Wall break structure — how the put wall acts as both target and gravitational pull. Must explain that dealers short the puts must sell stock as price approaches, creating a self-reinforcing move toward the wall.
The interdependency line for Section 2 must state: how the gamma flip connects to the armed trigger in Section 4 (armed trigger sits just above the flip to capture the acceleration); and how the put wall connects to Target 2 in Section 4 (put wall is why Target 2 exists).

6.7 Component 7 — Overnight Delta Injector
File: pipeline_interpreter_engine.py
Action: Add build_overnight_delta() function at bottom of file
This function is called by prepare_interpreter_session.py during morning mode. For each carry-forward ticker, it produces a compact OVERNIGHT_DELTA block that is injected into the triage prompt the following morning.
The overnight delta must assess:
Gap: did the stock gap up or down overnight? By how much?
Kill switch check: is the overnight gap price above the kill_switch_level? If yes → mark thesis as KILL_SWITCH_TRIGGERED in the delta block.
Trigger check: did the overnight gap price pass through the probe_trigger or armed_trigger? If yes → note as TRIGGER_APPROACHED_OVERNIGHT.
Macro shift: any overnight macro changes from the new enrichment delta vs previous session.
News: any overnight news mentions for this ticker from the newsroom brief.
Output format (injected into triage prompt):
OVERNIGHT_DELTA_WFC:
previous_verdict: WAIT
previous_ts: 20260522_1430
overnight_gap: +0.3% (opened at $76.14)
kill_switch_status: SAFE ($77.50 not breached)
trigger_status: AWAY (probe trigger $75.00 not tested)
macro_shift: NO_SIGNIFICANT_CHANGE
news_flags: NONE
carry_forward_action: CONTINUE_MONITORING

7. Thesis Identity Rules
These rules determine when a thesis persists across sessions versus when a new thesis is created. They are enforced in thesis_registry.py.
7.1 Thesis Persists When
Same direction (LONG_PUT stays LONG_PUT, LONG_CALL stays LONG_CALL)
Kill switch level has not been breached at any point between sessions
Same approximate strike zone (within ±$2.50)
Active thesis flag is True
Pipeline re-run produces same direction for this ticker
7.2 New Thesis Created When
Direction flips on the new pipeline run (PUT → CALL or vice versa)
Kill switch was breached at any point — old thesis is closed with reason="kill_switch_breached"
Trader runs /story TICKER --fresh explicitly
Pipeline produces MISDIAGNOSED verdict for this ticker
More than 5 calendar days have passed since the thesis was first formed without activation

10. Story HTML Output Specification
10.1 File Structure
outputs/
{ts}/                                 ← existing timestamped run folder
raw_response_{ts}.txt               ← existing
trade_brief_{ts}.csv                ← existing
interpreter_{ts}.html               ← existing deep-dive output
story_{TICKER}_{thesis_id}_{ts}.html  ← NEW story output
story_brief_{TICKER}_{ts}.csv         ← NEW story brief CSV
10.2 HTML Layout Sections
The story HTML document has this structure from top to bottom:
Header bar — identical to existing interpreter header: AVSHUNTER branding, EXECUTION PERMISSION watermark, ticker name, verdict badge, timestamp
State chain timeline — horizontal strip showing all previous verdicts for this thesis_id with timestamps and clickable links
Update banner — only present on CHART_UPDATE/OPTIONS_UPDATE/MACRO_UPDATE files. Shows what changed, when, and which sections were regenerated
Story progress bar — eight clickable pills (1 Macro, 2 Market makers, 3 Liquidity, 4 Thesis, 5 Chart, 6 Options, 7 Risk, 8 Verdict) that scroll to the relevant section
Eight section cards — one per section, each with badge, content, and INTERDEP footer
Footer — existing EXECUTION PERMISSION footer
