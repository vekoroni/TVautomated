## Runtime impact and measurement

Metadata-only inventory: MA_Inputs has **380 files / 4,479,734,109 logical bytes** (4.48 GB decimal, 4.17 GiB), latest file modification 20 November 21:50:47 UTC. Classic outputs contain **141 files / 18,423,464 bytes**, latest modification 10 August 19:01:03 UTC. File modification time does not prove when a model last ran or whether newer reports exist under run-scoped interactive_desk directories. No read errors occurred in these two inventories.

Source mechanism establishes overhead, not a measured elapsed-time saving:

- `on_pipeline_complete` force-copies its primary file, then recursively enumerates the output directory with a one-hour freshness window. Matching destination size/mtime can skip additional copies, but not enumeration/stat checks. Repeated hooks can scan the same run; call-site count is not invocation count.
- Routing flattens by basename; stopping this is not permission to alter canonical identities. Current skip rule compares size and mtime rather than content.
- Mandatory Morning copy verification reads source/destination hashes for four required artifacts in addition to copying them. Preserve the underlying canonical verification while removing duplication.
- Evening freeze compresses and hashes a full book on first publication; restarts validate an existing package. Preserve immutable EOD evidence if still needed, so not all this CPU/I/O is removable.
- Lab provider setup/imports affect startup; report calls add on-demand latency/cost. These are distinct from Evening/Morning runtime. Decommissioning must not replace them with synchronous automatic agent calls.
- Macro compatibility writes and optional watcher/capture work add independent overhead. The previously reported ~900 MB/run is unverified and must not be claimed as measured savings.

When execution is approved, measure paired original/retired runs on frozen inputs, same environment and cache policy, separately for Evening, orchestrator Morning, direct Morning, finalizer recovery, Lab startup and explicit report attempts. Use multiple paired repetitions for offline filesystem stages, report median/range and bytes scanned/read/written, copy counts, hash/compression time and total wall time. Do not sum nested stage durations or attribute provider/network variation to this retirement. Retained immutable freeze work stays in both baselines. Capture instrumentation belongs in the approved implementation/validation work, not this task.

Hard acceptance: zero retired sync, inference, provider and capture entry points through supported paths; the K10 snapshot library remains explicitly allowed; no new MA_Inputs writes/recreation; unchanged canonical data/permissions; retained handoff integrity. Runtime benefit must be measured, with any retained cost explained. No invented percentage or time-saving target.
