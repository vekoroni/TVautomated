## 2. c07 — arbitrated in favour of the code (FIXTURE_CORRECTED)

`test_c07_one_minute_volume_uniformly_allocated_and_labelled` made six
assertions about volume allocation and one about the cadence label. **All six
allocation assertions passed.** Only the label failed:

    AssertionError: 'COARSE_DATA_LOW_CONFIDENCE' != 'ONE_MINUTE_ESTIMATED'

The shared C-05/C-06/C-07 fixture supplies three bars at +0, +5 and +31
minutes. `market_structure/profile.py::_profile_cadence` derives the interval
from the median timestamp delta — median(5, 26) = 15.5, rounded to 16 — which
is not a recognised cadence, so it reports `COARSE_DATA_LOW_CONFIDENCE`. The
fixture never contained one-minute bars.

**Against AVS-SD-002 §9.1** ("estimate volume across touched bins only when the
method is disclosed") the production code satisfies both halves: it allocates
`row.volume / len(touched_bins)` uniformly, and it discloses the estimation
basis through `data_quality` and `cadence_source`. **The code is right; the
assertion was the defect.**

Resolution:
* The C-07 property is now asserted on the fixture's real cadence, and the
  test also pins `cadence_source` and `interval_minutes` so the disclosure
  itself is covered.
* A new test, `test_c07_one_minute_cadence_is_labelled_one_minute_estimated`,
  supplies twenty genuine one-minute bars and asserts the
  `ONE_MINUTE_ESTIMATED` label plus uniform allocation — so correcting the
  fixture loses no coverage.
* The bar geometry is untouched: C-05 and C-06 share this fixture and depend
  on the +31-minute bar falling in TPO period 1.

The sibling finding QT-D05 was arbitrated in the **opposite** direction (the
code was right there too, but the tester's independent implementation was
wrong) — see `QT-D05_arbitration.md`. Neither outcome was assumed in advance.

## 6. Fixed: the shared fixture session date (FIXTURE_CORRECTED)

Six tests across `test_flow.py` and `test_functionality.py` died before
asserting anything:

    ValueError: 2026-08-30 is not an XNYS session

2026-08-30 is a **Sunday**. `canonical_data/session_clock.session_bounds`
rejects a non-session date, so every test reaching the market-observation
resolver aborted in setup. Two separate expressions of one defect:

1. `session = date(2026, 8, 30)` in both files -> Friday `date(2026, 8, 28)`.
2. The five `tests/fixtures/marketdata/option_quote_*.json` and
   `option_chain_list_sizes.json` payloads carried `updated: 1788120000`
   (2026-08-30T20:00Z, the same Sunday). The chain resolver requires >= 80% of
   quote timestamps to fall on the session date, so correcting only the test
   date moved the failure from "not an XNYS session" to "option-chain
   quote/session mismatch". Epoch corrected to 1787947200
   (2026-08-28T20:00Z).

**Deliberately not changed:** `test_functionality.py` line 706,
`datetime(2026, 8, 30, 12, 0, tzinfo=timezone.utc)  # Sunday, CLOSED`. That
instant is Sunday *on purpose* — it proves the CLOSED session state. A blanket
find-and-replace corrupted it on the first attempt; the change was reverted and
redone against `date(...)` constructors only.

Verified no regression: `tests/test_msi_agent1_data_foundation.py`, the fourth
consumer of those fixtures, stayed at 12 passed.
