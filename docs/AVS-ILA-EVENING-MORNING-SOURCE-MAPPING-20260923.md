## 1. Boundary and ownership rules

The Lab must display a single governed opportunity population. It must not decide the market thesis by picking the richest-looking CSV. Each field has one semantic owner, a point-in-time meaning, and a permitted update event:

1. **Evening publishes the frozen thesis.** The completed-session evidence session, direction, structural target and invalidation, planned hold, selected structure/contract identity, and original macro packet are immutable for this run. Morning may compare or supersede through a recorded event, never silently overwrite them. Evening candidate rows are not a current executable quote.
2. **Morning publishes new observations and a validation event.** The underlying price and its provider time, developing-session evidence, exact selected-contract quote and its provider time, gap/runway, and Morning event mode belong to Morning. A post-open contract refresh and a pre-open thesis check are different modes. Missing one does not mean all Morning work was not run.
3. **Execution Gate owns actionable permission.** Morning `GO`, `GO_LIMIT`, `FLAG`, etc. and Lab `GO` are not interchangeable fields. Lab verdict is a derived read model that must reconcile with the exact Morning/Execution Gate event; no EOD or legacy fallback may grant execution authority.
4. **Macro, DOI, EV3, GARCH, WBS, market structure and Interpreter each retain their own calculation authority.** Macro and Interpreter are advisory. A later macro packet is not silently substituted into the frozen Evening thesis. A different DOI-preferred contract does not silently replace the governed contract or its quote.
5. **Every display value needs provenance.** A value's run, ticker, thesis/contract identity where relevant, semantic owner, source dataset ID/hash, provider observation timestamp, fetch timestamp, and calculation version must be retained. A copied field in `morning_validated_trades` does not make Morning the semantic owner of a frozen Evening fact.
6. **Absence is typed.** `NOT_RUN`, `NOT_APPLICABLE`, `PROVIDER_UNAVAILABLE`, `MISSING_PROJECTION`, and `NOT_SELECTED_FOR_INTERPRETER` are distinct. Never turn a missing observation into zero or a favourable decision.

## 4. Current failure, why the existing checks passed, and required reconciliation

The actual path is `morning_gate.py` -> `morning_validated_trades` (1,550) -> `morning_handoff_finalizer.py` -> `write_final_opportunity_book()` (1,550) -> Lab `_governed_lab_book()` -> `merge_all_opportunities()` (359 actionable rows allowlisted) -> `_compact_lab_signal()` -> browser. The finalizer checks row count and selected authority decisions; it does **not** require the Morning event/mode fields in the published book. The Lab's earlier EIL/Morning enrichment is overwritten with that book. The accepted handoff's validation facts are outside the advisory overlay allow-list, which correctly protects authority. However, the allow-listed evidence is not being overlaid either: the merge rejects every accepted row before the allow-list runs (section 4a). Static UI tests verify that mode-aware helper functions exist, not that published rows contain the mode they require.

### 4a. Accepted handoff overlay is rejected on every row (finding added 2026-09-23)

**Observed.** For run `20260922_223221` the Lab API `lab_reconciliation` block reports `actionable_handoff_count=359`, `actionable_rows_overlaid=0`, `actionable_rows_rejected=359`, with every exception `ACTIONABLE_IDENTITY_MISMATCH:selected_contract_symbol`. Runs `20260922_000106` (249 rows) and `20260920_203115` (206 rows) show the identical 0-overlaid result. Every published row carries `lab_actionable_handoff_member=False`; the 359 handoff members carry `lab_actionable_overlay_state=REJECTED_IDENTITY_MISMATCH`.

**Mechanism.** `domain/dynamic_options_projection.py` (`merge_all_opportunities`, introduced 12 Sep 2026, commit `d0c5cbc`) includes `selected_contract_symbol` in `_STRICT_PROTECTED_MATCH_FIELDS`: when the handoff row has a value, the full-book row must have the same value. `contracts/interpreter_handoff_materializer.py` (`_canonical_contract`) synthesises `selected_contract_symbol` on every bundle from `selected_contract_symbol` / `morning_selected_contract_symbol` / `contract_symbol` / single-item `selected_contract_symbols`. `FINAL_BOOK_FIELDS` in `contracts/lab_control.py` has never contained `selected_contract_symbol` (checked at `667620e`, `ff07645`, `6ab278b`, `d0c5cbc`, `46083ee`); the book publishes `selected_contract_symbols` (plural) and `morning_selected_contract_symbol`. The base row therefore always fails `_has_value`, and the row is rejected before any allow-listed field is copied.

**Masking.** `intelligence-lab/intelligence_lab.py` (`_governed_lab_book`) overwrites the merge result's `status=PARTIAL` with the handoff manifest's `reconciliation_status=PASS`, so the API reports `PASS` while dropping the whole overlay. `tests/test_doi10_projection_integration.py` passes because its fixtures place `selected_contract_symbol` on both sides.

**Characterisation (read-only replay, no files changed).** Replaying the real 1,550-row book against the real 359-row handoff: as published, 0 overlaid. Filling only `selected_contract_symbol` on the book rows from the materializer's own alias chain: 359 overlaid, 0 rejected, no other identity or protected-field mismatch. The single missing field is the whole cause.

**Measured effect on the Lab.** When the overlay applies, 17 allow-listed fields go from 0 to 359 populated rows: `change_status`, `comparison_status`, `contract_ask_change`, `contract_ask_change_pct`, `contract_ask_size_change`, `contract_bid_change`, `contract_bid_change_pct`, `contract_bid_size_change`, `contract_mid_change`, `contract_mid_change_pct`, `contract_spread_change_pp`, `current_quote_snapshot_id`, `current_spread_fraction_mid`, `current_spread_pct_of_mid`, `quote_age_affects_thesis`, `quote_age_seconds`, `quote_timestamp_utc`. The remaining allow-listed names (`interpreter_*`, `ms_*`, `underlying_nbbo_*`, `underlying_last`, `overnight_gap_pct`, `session_state`) do not change because the handoff book rows do not carry them; their absence is a separate producer gap, not this defect. In the register, `quote_timestamp_utc` (`GAP_VISIBLE_OR_REQUIRED`, 0 rows) is explained entirely by this rejection.

**Related consumer defect (Interpreter Desk, uncommitted working tree).** `pipeline_interpreter/confluence_evidence.py` reads `invalidation_spot` (0 of 1,550 book rows; the governed column is `invalidation_price`) and `morning_thesis_result` (present in no producer and absent from this register; the governed name is `validation_transition`). Every desk report is therefore told `GOVERNED_LEVELS_MISSING` and Morning `NOT_RUN_OR_NOT_ACCEPTED` even for confirmed rows. This is the same class of field-name mismatch and is the most likely cause of the PFE `REPORT_VALIDATION_FAILED` receipt on 2026-09-23; the failure receipt does not record which validation rule fired.

**Disposition.** Blocking for Lab publication invariants. Decide the single owner of `selected_contract_symbol` (publish it in the book contract, or make the merge accept the materializer's alias chain), pin the current 0-of-359 behaviour with a characterisation test on the stored run, then fix in place and stop overwriting the merge status with the manifest status.

**Implemented 2026-09-24** per `AVS-SD-ILA-003-SELECTED-CONTRACT-IDENTITY-CONTRACT.md` section 10 (book publishes the singular identity with a typed state; Lab reports the merge status and flags rejections; Interpreter reads `invalidation_price` and `validation_transition`). Read-only replay of `20260922_223221` reconciles 359 of 359. Stored book of that run republished 2026-09-24 (backed up; ILA-003 section 10) and the running Lab now serves it with status PASS, 359 overlaid, 0 rejected. Not committed; live acceptance on the next Morning run outstanding.

For the sampled run, every Morning row is `POSTOPEN_CONTRACT_REFRESH`. All 1,550 Morning rows have a validation-event file, but `morning_execution_mode`, `validation_event_id` and `validation_transition` are absent from the entire 1,550-row final book. `lab_verdict` and `morning_execution_permission` are present. Thus `GO` beside `NOT RUN` is a **systemic, partial-handoff defect**, not a LUNR exception or evidence the browser failed to refresh. The final manifest records technical `PASS` but semantic `DEGRADED` and 169 missing selected invalidation levels; that distinct issue is not resolved by this map.

**Required publication invariants** after Morning:

- Source Morning row count = validation-event count = full-book row count = Lab API row count, subject only to an explicitly documented excluded population.
- Per ticker: run/thesis/structure/contract/quote identity matches; Morning mode, event ID, transition, observation cutoff and current price agree with source. A post-open event may report thesis confirmation, but must never be labelled a *pre-open* check.
- `GO`/`GO_LIMIT` display requires a compatible Morning event, execution decision and quote identity; if the Lab projection loses context, mark the display `INCONSISTENT_DATA` and withhold the trader-facing GO label while preserving the underlying source artefacts.
- Show provider observation time and acquisition time separately; never label a 1–20-session thesis stale merely because a quote ages. Quote age describes execution context.
- The API/cache signature must include the final book, Morning event/summary and accepted handoff. The browser should show their run ID, publication version and refresh time. A Morning refresh must not rely on a restarted Lab server.

## 5. Removal decisions: what is and is not safe now

The companion register records 266 UI-referenced names that are neither direct final-book columns nor governed UI aliases. That is **not** proof that 266 fields should be deleted: some are deliberate fallbacks, prefixes assembled dynamically, or fields on other API payloads. Five names appear twice in `FINAL_BOOK_FIELDS` (`usmi_sector_alignment`, `usmi_alignment_priority`, `usmi_alignment_reason`, `usmi_scenario`, `usmi_authority`); deduplicating schema declarations is safe only after checking CSV order/hash consumers.

| Candidate | Current disposition | Required proof before removal |
|---|---|---|
| Legacy `mv__*` Morning tab, `morning_validation.py` instruction | **Replace as a unit**, not preserve as a false `NOT RUN` surface | bind to governed Morning event/decision fields; screenshot/API and EOD/Morning parity tests for GO, FLAG, BLOCK, pre-open and post-open |
| Ambiguous `quote_timestamp_utc` label | **Rename/role-bind**, not simply drop | confirm selected Morning/current quote timestamp and quote identity on rows with and without a current quote |
| `target_spot`, `invalidation_spot` UI/producer aliases | **Retain until controlled alias migration.** `invalidation_spot` is also read by the Interpreter confluence builder against the frozen book, where it is empty on every row (section 4a) | compare target/invalidation identity with governed book on CALL, PUT, missing-stop and reselection cases; add the Interpreter Desk as a consumer |
| `selected_contract_symbol` | **Not a UI alias: blocking identity-contract mismatch** (section 4a). Do not remove; resolve ownership | characterisation test on run `20260922_223221` showing 0 of 359 overlaid, then a business-rule test requiring 359 of 359 |
| Legacy capital/position-size display values | **Do not let them allocate capital**; hide only after UI/Interpreter consumer audit | verify human-determined sizing still shown and no decision or ledger reads deleted key |
| `source_payload_json`, provenance IDs, validation event files, stage CSVs | **Retain** as evidence even if omitted from compact browser payload | immutable replay and audit needs; not redundant merely because not shown in the wall |
| Screenshot-only diagnostics | **Review for removal from active wall**, retain historical evidence | prove no active Interpreter/CLI/test consumer and that numerical market-structure evidence replaces its role |

No data field or UI control is removed in this mapping stage. Removal requires an exact consumer search, source equivalence, controlled diff, regression and one EOD-to-Morning replay. A blank field is a repair/availability question, not a deletion criterion.

## 6. Implementation order after mapping sign-off

1. Freeze a versioned Lab read-model contract with explicit Evening-frozen, Morning-observed, Morning-decision, advisory, and presentation-only namespaces. Keep existing IDs and authority fields protected.
2. Materialize the Morning mode and validation event on the **full population** before Lab publication; carry them through the governed final book with provenance. The 359-row handoff stays an actionable/Interpreter subset, not a substitute population.
2a. Resolve the `selected_contract_symbol` identity contract so the accepted handoff actually overlays (section 4a), and report the merge's own reconciliation status rather than the manifest's. Fix design: `AVS-SD-ILA-003-SELECTED-CONTRACT-IDENTITY-CONTRACT.md`. Correct the Interpreter confluence field names (`invalidation_price`, `validation_transition`) in the same slice.
3. Replace legacy Morning tab/quote bindings with governed role-specific fields; show unavailable source observations honestly. Display EOD and Morning values side by side where both matter.
4. Make row/event/field and decision-evidence reconciliation release-blocking for the Lab projection, then verify cache/browser refresh without restarting the server.
5. Prove a field is unused before removing it. Run EOD, post-open, pre-open, missing quote, missing invalidation, contract reselection, CALL and PUT tests plus a stored-run replay.

This document proposes a source contract; it does not certify that the current Lab is trader-ready.
