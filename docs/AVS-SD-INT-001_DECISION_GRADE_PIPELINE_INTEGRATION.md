# AVS-SD-INT-001 — Decision-grade AVSHUNTER integration and intelligence layer

**Status:** proposed solution design; no production activation granted

**As-of:** 26 September 2026; branch `avs-fix-001`, inspected HEAD `e0c4a95`

**Business owner:** human trader; **technical authority:** existing governed Evening/Morning contracts

**Scope:** shares, long calls and long puts; 1–20-session thesis and monetisation paths

**Change rule:** this design reconciles existing registers; it does not authorize a pipeline run, provider spend, broker order, capital allocation, model promotion, or deletion of evidence.

## 1. Outcome and standard of proof

The pipeline must produce a trustworthy, reviewable list of dated ticker theses, explain direction and stage, show permitted expressions and current quote quality separately, and help a human decide whether and when a long share/call/put can be monetised. Morning validates and updates the frozen Evening homework; it does not need to recreate the thesis. A quote, timing problem, missing option, uncalibrated score, or invalidation observation cannot silently erase an opportunity or its history. The human controls entry and exit. “80% confidence” means **decision-grade completeness and internal consistency**, not an asserted 80% realised trade win rate. We will report empirical calibration and ask-to-bid outcomes separately; no output quota or guaranteed-return claim is allowed.

This is an additive integration programme, not a wholesale pipeline replacement. Existing deterministic authority and the current Lab book remain the baseline until every replacement has parity evidence and a versioned rollback. Work begins with defects that corrupt truth or make releases irreproducible, then adds the reasoning layer in shadow, then validates prospective utility.

**Keep the solution as simple as the evidence permits.** A successful build may be one corrected rule, field mapping, state transition or calculation; it need not be a new model or subsystem. Use a model only when a simpler governed rule fails a predeclared comparison. Research must lead to a build decision, not grow indefinitely as a parallel product.

The latest read-only cohort research gives a concrete reason to separate thesis and expression: 35 of 112 target-first stock cases had a non-positive exact-option paper outcome, while 105 option-positive observations had not first reached the five-session stock target. Those are sample-specific research observations, not a trade rule or prospective win-rate estimate. They require the pipeline to expose both the underlying path and the exact contract's executable path, including opportunities a human could monetise before the structural target.

## 3. DDD context map and non-negotiable authority

```text
Run Planning/Provider Finality -> Canonical Evidence (Phantom + Actuarial + macro)
                                 -> Discovery/Vanguard (frozen opportunity thesis)
                                 -> DOI/Expression (contract family, liquidity, economics)
                                 -> Evening Book + immutable snapshot
                                 -> Morning Thesis Validator + append-only observations
                                 -> Lab read model -> Interpreter/WAR advisory report
                                 -> Human decision/fill -> Outcome ledger -> Research/Calibration
```

No downstream consumer may silently re-author an upstream fact. Every materialised field carries owner, value, status (`MEASURED`, `DERIVED`, `INFERRED`, `MISSING`, `CONFLICT`), source ID/hash, event/source timestamp, observed-at timestamp, as-of cutoff, calculation version and run ID where relevant. Reject future-to-cutoff evidence. Later Morning/live/broker observations append to, rather than overwrite, the frozen EOD claim. `run_id + ticker + side + exact OCC contract + source hash` are joins, never proximity or display-string matches. Distinguish `NO_DATA_AT_SOURCE`, `NOT_REQUESTED`, `PROVIDER_FAILURE`, `NOT_APPLICABLE`, `PROJECTION_MISSING` and `UNVERIFIED_HISTORY`; none becomes numeric zero.

The authority axes are independent: (1) thesis state and stage; (2) data sufficiency/provenance; (3) expression and current quote state; (4) research rank; (5) human decision/fill. A quote or model can change axes 2–4, not thesis direction. Hard identity/data correctness and authoritative invalidation checks remain hard. Macro/sector and Interpreter/WAR are advisory; Worker 3 remains paused; neither assigns capital or places orders. A breached level is a dated event and may trigger recovery monitoring, not historical deletion. An expired contract remains in history while a valid ticker may be re-expressed.

## 4. End-to-end target behaviour and changes

### 4.1 Acquisition, two databases and macro

Run Planning resolves the last completed XNYS session; provider-finality requires settled, session-aligned chain and underlying evidence. Phantom owns point-in-time exact option identity, bid/ask, Greeks, IV and quote trajectories; Actuarial owns distinct underlying/history/forecast observations. Neither database supplies a missing quote from a different session by convenience. Compute missing Greeks only with disclosed input/provenance; never overwrite provider Greeks. Record source refresh cadence (daily, weekly, monthly) separately from file-build time. Keep GEX sources reconciled with session and method disclosure; a dual-source difference is a conflict to show, not an automatic macro veto. The macro builder normalises the required contract, archives the immutable packet and validates publication **before** downstream acquisition/pinning; the 25 Sep fallback contract-version abort must be a regression fixture. Macro source release/event times, cross-asset capture times and independent Colab batches are compared by dated temporal policy, not host/IP or same batch ID. A missing packet is typed advisory degradation, not a fabricated complete macro.

### 4.2 Direction, stage and thesis

Discovery/Vanguard proposes CALL-side rise, PUT-side decline, or unresolved/neutral scenarios from price structure, breadth, flow proxies, catalyst and market profile. Direction and stage are computed **before** choosing a contract. The reasoning chain is: macro regime and money transmission -> sector leadership/headwind -> ticker-relative flow and company catalyst -> price structure/stage/trigger -> counter-case -> expression economics. A sector headwind **invokes** a PUT hypothesis; it cannot overturn a well-evidenced idiosyncratic CALL. Confirm directional evidence from independent families; correlated indicators from one feed get one vote. Preserve VST-type sector/constituent mappings from the separate universe work; do not edit that universe in this programme. Until its correction is proven, conflicting/unmapped sector tags are disclosed and excluded from flow inference, not replaced by an assumed match. Freeze EOD thesis, target, invalidation candidates and cutoff with versions. Missing target or authoritative invalidation makes execution planning incomplete, not opportunity deletion; a selected row must never appear execution-ready without it.

### 4.3 Contract family and monetisation

For each directional thesis, generate a governed long-call/long-put family, plus long shares for bullish comparison. Evaluate exact contract, DTE relative to 1–20-session holding horizon, delta, IV, ask/bid spread, size, volume, OI, quote timestamp, option mark path and scenario payoff. PCR is chain/expiry/region context; OI is positioning and volume is activity, neither is signed order flow. Do not treat theoretical midpoint as an executable result. Keep structural-target intrinsic value as a **labelled scenario**, never `rr_predicted` or expected return. Show early/mid/late and IV/spread/spot stresses, ask entry and conservative bid exit, a reachable move and flat/invalidation cases. A clear two-sided quote is needed for `EXECUTABLE_NOW`; no quote yields `MONITOR/NO_CURRENT_EXECUTABLE_QUOTE` while thesis persists. Consider alternatives and contract switching with hysteresis only in shadow until evidence confirms improvement. User entry/exit and interim 10% monetisation remain human choices; the pipeline supplies path observations and reminders, not forced close rules.

### 4.4 Evening, Morning and Lab

Evening publishes the full opportunity book with explicit `THESIS_READY`, `TRIGGER_WATCH`, `REVIEW_MISSING_DATA`, `INVALIDATED_OBSERVATION`, expression/quote states and reason codes, rather than collapsing every row into GO/BLOCK. It produces a small evidence-backed focus list but retains the full population. Morning records pre-open thesis validation separately from post-open exact-contract quote refresh, then appends change events to the EOD parent. The Lab projects the latest *accepted* event on all rows and displays EOD versus Morning field roles, selected contract identity, as-of and publication ID. Morning completion requires terminal marker, reconciliation and full-book materialisation; a candidate subset is not the full-book source. A Lab projection failure shows `PROJECTION_INCOMPLETE` and withholds only the Lab actionable affordance; it does not relabel the source thesis or hide the ticker. Add browser/cache parity tests so long-lived Lab sessions refresh without a restart.

Correct every trader-facing zero-from-blank, misowned field and duplicated/placeholder calculation. Specifically reconcile the 5/10/20-session **cumulative** volatility budget against legacy incremental `garch_expected_move_6_10d/11_20d` consumers; rename/version the legacy increments. Recompute convexity from its real input dashboard or mark it unavailable; never present campaign verdict {0,2,3} as a measured convexity score. Gamma and macro can remain visible with their source, timestamp and limitations. GARCH/bias multiplier and “cheap convexity” language remain unvalidated until held-out forecast tests pass. `rr_predicted` is removed or relabelled on every row and the scenario fields appear with explicit unavailable reasons. Keep capital allocation fields disabled.

### 4.5 Intelligence layer: Interpreter + WAR

The human may select **one to five** tickers from the same governed Lab book. Reuse the frozen EOD Interpreter snapshot, accepted Morning delta and report/conversation persistence; do not add screenshot automation, a second trade gate or a new independent candidate triage. WAR is an **advisory projection** after an existing saved Interpreter report and named evidence sources are ready. First close the untracked exact-quote join dependency and clean-checkout import. Then integrate the six proposed pure WAR components (exact-contract quote join, temporal truth, transmission chain, corroboration, coverage summary, provenance renderer) through one versioned assembler; compare old WAR v1 and v2 side by side before changing the displayed default.

The report must answer with sourced data or `UNKNOWN`: what is the macro event/rates/USD/liquidity/volatility state; where is sector money plausibly flowing; why is this ticker moving relative to sector/index; who controls price, what stage/trigger/trap/invalidation is observed; where is the crowd/wall and what liquidity is **inferred**, not measured; which exact long call/put or shares route has viable current economics; what is the strongest opposite case and what would falsify each case? It must show event -> macro -> sector -> ticker -> contract links as measured/inferred/missing, not invent flows from descriptions. Use the freshest **point-in-time valid** evidence for each question; source dates need not all equal the EOD date. A post-EOD quote is valid for a later report cutoff but must not be back-written into EOD. Provider news may add a narrative only with source/release time and corroboration. Persist canonical report JSON, render HTML only from that saved JSON, make reopening provider-free, and allow scoped follow-up questions. One fluently written paragraph cannot repair missing, conflicted or mismatched Lab data. Keep token/cost bounds and no automatic retry on unknown provider outcome.

### 4.6 Outcome learning and decision intelligence

Capture all selected and rejected opportunities, frozen rule/version, human action and actual fill if provided. A quoted paper opportunity is not an executed trade. For each exact contract, measure target-first, invalidation-first, neither and ambiguous paths over 1/5/10/20 sessions; retain censored/unverified paths as such. Measure first positive bid, first +10% ask-to-bid bid, MFE/MAE, time to monetisation and severe loss with spread/IV stress. Separate ticker correctness from option profitability and shares comparison. Phantom paths must have provider timestamps and contract identity; Actuarial features must be as-of aligned. Never synthesize a missing option quote from stock price or a lower-trust snapshot to complete a path.

Start with a transparent, frozen baseline and compare a time-aware competing-risk estimator, constrained boosted interaction model and Bayesian/dynamic updater **on the same eligible population**. Preserve a novelty lane for previously missed winners; no single filter may erase them. Time-separate training/validation/test with purge and embargo based on maximum outcome horizon; log every variant tried. Calibrate on data distinct from fitting data. Evaluate top-20/top-50 review precision, coverage, missed high-payoff opportunities, ask-to-bid net outcome, severe downside, calibration and uncertainty, by CALL/PUT and hold bucket. A small attractive slice (for example 78/186 target hits) is a research lead, not a transferable 41.9% trading probability; two 500% tails do not justify a fitted extreme-value law. Research models cannot obtain production ranking or gate authority until prospective, pre-registered acceptance. Human exit choices and later market evolution remain explicit limitations.

Test the named production import closure from a clean checkout; then separately exercise dynamic routes. The v1 WAR quote-join dependency is already committed, while v2 remains local-only. Convert each research finding into a small accepted rule/fix, a gated experiment, or a reasoned rejection; do not implement a document wholesale. Govern the approved register/amendments and this design. No production path change yet. **Exit:** reproducible baseline manifest, explicit disposition for every finding and failing tests for each confirmed defect.

**S1 — Truth and publication (P0).** Fix macro fallback normalization/publication before acquisition; exact as-of/provider finality/GEX conflict disclosure; selected-handoff target/invalidation provenance; tradeability semantics; book and row reconciliation. Isolate the universe-mapping work in progress and assert its published version before making sector inference. **Exit:** stored aborted-run replay no longer reaches a late macro contract mismatch; no false execution-ready manifest, no missing actionable invalidation; no feature authority change.

**S2 — Lab field/geometry repair (P0).** Correct EOD/Morning event read model, source/contract/quote joins, full-book cache refresh, blank-versus-zero, legacy R:R label, cumulative GARCH display and convexity provenance. Keep old UI available behind a feature flag until parity. **Exit:** field-level source matrix reconciles frozen stored runs through API and browser; no GO/“Morning not run” contradiction, no silent missing numeric values.

**S3 — Deterministic expression and advisory reasoning (P1).** Repaired scenario economics, DOI family shadow, share comparison, quote lifecycle and reversible state axes; exact-broker observation only for selected names. Introduce deterministic macro-sector-ticker confluence with independent evidence families. Integrate governed WAR components as v2 alongside existing v1; Worker 3 stays off. **Exit:** same EOD/Morning rows preserved, old/new expressions compared, no authority drift, complete provenance/coverage disclosure, bounded one-ticker provider canary only with operator approval.

**S4 — Outcomes and research (P1/P2).** Audit both databases; run isolated writer/storage canary before routine exact-contract capture. **S5 — Controlled release and forward acceptance.** Run focused, cross-domain, adversarial and broad offline suites; build from a clean checkout, inspect diff/secrets/space, tag a release with code/config/schema hashes, rollback plan and capability flags. Commit is the final step after the implementation and required tests pass, not a substitute for them.

## 7. Test architecture, acceptance and rollback

For each slice, first write a failing contract test for the real defect, then a minimal domain change, then an integration/replay test. Minimum matrix: identity and timestamp properties; null/NaN and contradictory-source cases; macro source unavailable/stale/dual conflict; run restart and duplicate observation; CALL/PUT/no-chain/no-quote/expired option; EOD/Morning opposite move and later recovery; missing target/invalidation; Actuarial-versus-Phantom as-of alignment; Lab refresh without restart; Interpreter report output overrun/unknown outcome/prompt injection; read-only broker enforcement; shares-versus-option comparison; disk/WAL/duplicate integrity on isolated canary. Replay a frozen successful run **and** the 25 Sep aborted run. Never use the same cohort to discover a filter and claim its held-out performance.

Required quantitative dashboard per release: provider-finality state and chain timestamp coverage; full-book row counts and source hashes; actionable invalidation coverage; null and conflict counts per Lab field; exact option quote coverage and age by side; valid EOD/Morning join rate; v1/v2 WAR coverage and unsupported-claim count; 1/5/10/20 option-path coverage; measured net ask-to-bid opportunities (including +10%), missed winners, severe losses, calibration/uncertainty and matched comparator. Stratify by CALL/PUT, thesis horizon, stage and source quality. A good result in a tiny subgroup is reported with n and interval, not promoted by a headline rate.

Rollback is capability-flagged: old deterministic thesis/selector and Lab book remain callable; new model, broad family preference and WAR v2 default can be disabled independently without rewriting frozen history. Database migrations are additive and reversible with scoped backups; no full live Phantom copy where disk headroom is unsafe. Preserve immutable input/receipt/report JSON. A failed provider or projection returns a typed degraded state, not a fabricated trade decision. Do not delete historical opportunities, run packages needed for research, or user-owned untracked files as part of this work.

### Definition of done for every slice

The required lifecycle is **test-driven design -> domain-driven design -> build -> focused tests -> integrate into the real pipeline path -> integration, replay and regression tests -> acceptance evidence -> commit last**. A design, isolated module, green unit test, shadow experiment, or commit on its own is not “done.” Each slice closes only when its production-path owner and caller are identified; its domain contract and authority boundary are documented; the pre-fix test fails for the intended reason; the implementation passes focused and cross-domain tests; the affected Evening/Morning/Lab/Interpreter outputs reconcile on stored runs; failure and rollback cases are exercised; the release manifest records what passed and what remains gated; and the final reviewed files are committed. Where live completed-session or paid-provider acceptance is required but not yet operator-authorised, status is **IMPLEMENTED_PENDING_ACCEPTANCE**, not done. Uncommitted work is **TESTED_UNCOMMITTED** at most, even if all tests passed. Any later fix reopens the relevant slice and its regression gate.

### Research retirement rule

For each research item, record its finding ID, decision, exact production rule/calculation or model version (if accepted), caller, test IDs, acceptance evidence and final commit. Once that trace is complete and the live route is verified, mark the paper **SUPERSEDED_BY_IMPLEMENTATION** and move redundant narrative to a dated archive; remove duplicate working copies only after checking they contain no unique point-in-time inputs, test cases, negative results or audit evidence. Preserve one governed source record and the original experiment/variant log so the result remains reproducible. Rejected ideas are closed with a short reason, not left as apparent unfinished fixes. Research that has not actually been integrated remains **OPEN**, even if code exists in isolation. No research file is deleted merely because a feature with a similar name was built.

## 8. Decisions and exclusions

There is **no** authority to reactivate Worker 3, allocate capital, place broker orders, impose a daily trade quota, use short shares/options/spreads, force an entry/exit on timing, or auto-enable a fitted model. A normal pipeline run, external provider call or paid Interpreter canary requires a separate operator instruction. The first implementation action is S0: govern the release/import baseline and write the truth-reconciliation tests; S1 and S2 repair the current product before any learning model can influence its outputs.
