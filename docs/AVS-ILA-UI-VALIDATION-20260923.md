## Verdict on the existing assessment

**Approve the core source-of-truth assessment with corrections.** The missing Morning context is a full-population publication problem, not a LUNR-specific or stale-browser problem. But the UI review reveals more broken presentation contracts than the previous assessment listed. It also shows why removal decisions must be tab-aware: a blank pane may be a legacy binding, missing upstream data, or a deliberately non-applicable observation. These are not equivalent.

The sampled run's final manifest says `pipeline_mode=MORNING_VALIDATION`, Morning phase `PASS`, and 1,550 Morning rows. All 1,550 Morning rows have `morning_execution_mode=POSTOPEN_CONTRACT_REFRESH`; the same number of validation-event files exists. The full Lab book has all 1,550 rows and retains GO/GO_LIMIT decisions and 1,368 selected quote timestamps, yet has **zero** Morning modes, event IDs, or validation transitions. The 359-row accepted Interpreter handoff has event IDs/transitions, not the Morning mode. The Lab overwrites its earlier Morning-enriched assembly with this full book. The advisory overlay allow-list cannot restore the governed event fields by design, and in practice it restores nothing: the merge rejects all 359 accepted rows on `selected_contract_symbol` before the allow-list runs (source mapping section 4a). This is partial integration, not evidence of a failed Morning computation.

## Why the tests passed despite the defect

The existing `tests/test_ila_morning_state_separation.py` checks that mode-aware JavaScript helpers and labels exist. `tests/test_doi10_projection_integration.py` checks population and allowlisted merge behaviour. Both are legitimate unit tests, but neither requires the **published full-book row** to contain the mode or validation event read by the UI. The existing 19 tests in those files passed in this review (`venv/Scripts/python.exe -m pytest -q -p no:cacheprovider ...`). That result cannot certify the browser's end-to-end field contract.

The browser's `canOpenEntry` helper checks `lab_tradeable`, verdict and coarse conflict/permission fields; it does not require the Morning validation event to be present in the displayed row. Conversely, `getMorningLifecycleBanner`, `getPreopenThesisState`, `getMorningDrift` and the Morning Val pane read missing or retired fields. A trader can therefore see a GO action beside “NOT RUN” without a failing automated test. The UI's `getExecutionCategory` also has a wide legacy fallback chain; a missing governed action must never be replaced by an older favourable label.

## Assessment corrections before design

1. The previous 926-name CSV is a **superset inventory** (620 declared final-book entries, 497 syntactic UI references, plus critical handoff fields), not a list of 926 actively visible independent facts. Five final-book names are duplicated in the declaration. A UI reference outside `FINAL_BOOK_FIELDS` is not automatically unused: it may be a presentation alias, a dynamic prefix, or a field on another API payload.
2. Validation event `THESIS_CONFIRMED` can be produced by the **post-open** path. The current JavaScript comment implying `validation_transition` is pre-open-only is false for this run. Adding that field blindly would change “NOT RUN” into the equally wrong “pre-open confirmed.” Mode and event provenance must be carried together.
3. Morning macro freshness and quote freshness are **different clocks**. “FRESH” for the 2026-09-22 macro packet refers to its governed source/cadence, not proof of a 2026-09-23 market update. Neither should be inferred from the Lab page load time.
4. Missing NBBO or canonical VWAP is not necessarily a projection defect. `live_price`/`live_vwap` are different observations and should be displayed with their own source/clock rather than renamed to fill blank cells.
5. No field is approved for deletion solely from this run. The defensible UI simplifications are to conditionally hide inactive legacy Entry Telemetry and to retire obsolete Morning-tab bindings **after** parity tests. Keep the evidence in run outputs for replay and Interpreter/audit use.
6. **The accepted handoff overlay is rejected on every row.** Lab API `lab_reconciliation` for this run: 359 handoff rows, 0 overlaid, 359 rejected, all `ACTIONABLE_IDENTITY_MISMATCH:selected_contract_symbol`; the same 0-overlaid result holds for the two preceding runs. The full book never publishes `selected_contract_symbol`, while the materializer always synthesises it and the merge treats it as a strict protected match field. The API still reports reconciliation `PASS` because the manifest status overwrites the merge status. Consequences for the screenshots: the `MISSING` quote timestamp in the MSI pane (`162007`) is `quote_timestamp_utc`, an allow-listed overlay field that would be populated on all 359 rows once identity reconciles; the blank `interpreter_*`, NBBO and canonical VWAP cells are **not** explained by this rejection because the handoff rows do not carry them. Replaying the stored run with only that one field filled overlays 359 of 359 with no other mismatch. Treat as blocking for the read-model design, ahead of any alias migration.

**Decision:** the source mapping is directionally correct, but the previous document should not be used as a build specification without the mode semantics, UI-tab rules, and end-to-end acceptance gates above. Proceed with a corrected read-model design, then implement in a separately tested slice.
